# Illustration engine architecture

MotionLab now has two parallel graph paths:

- Existing `graph` → `SceneGraphRenderer` → ThreeCanvas, unchanged 3D object schema and motion presets.
- New `illustrated` → `IllustratedScene` → recursive SVG layers and stateless 2D motion evaluation.

Both compile through the existing storyboard contract. The `SceneView` wrapper is shared by full composition and standalone previews so backgrounds, local timing and transitions agree. Earlier coffee React scenes remain selectable as bean/extraction/espresso; the benchmark now uses the new data renderer.

## Modules

## Coordinates and time

Nodes have local coordinates; parents compose affine transforms. Anchors are coordinates in the node's geometry, subtracted before scale and rotation. Animation tracks replace base properties. Path-following adds a cubic path offset. Times are shot-local seconds, evaluated from `useCurrentFrame()` / `useVideoConfig().fps`. Layer overrides replace target track arrays. Paint order is stable by z among siblings.

A 2D camera frames a world point at the stage center with smooth bounded interpolation. Top-level group depth adjusts pan for parallax. Text stays outside the camera transform. Clips use direct SVG geometry with accumulated transforms; masks render in local coordinates. Definition IDs are namespaced per mounted scene instance. Recursive clip/mask dependencies are rejected.

## Extending

`IllustratedScene.tsx` owns scene layout; `rendering/IllustrationCanvas.tsx` owns the SVG world and `rendering/VectorNode.tsx` owns each node. Timing implementations are in `storyboard/timing/`; preview CLI steps are in `scripts/preview/`. Compatibility entry points retain their previous exports.

Draw a new asset with existing node helpers; call `registerIllustrationAsset` with bounds, layers, source, license and style. Give layers unique target IDs. Reference it from a shot asset node and author tracks or layer overrides. No new React scene is required for an ordinary illustrated explainer. New primitive kinds, paint servers or deformation systems require a schema and renderer adapter, plus tests and actual frame review.

## Scope and limits

- Output dimensions/FPS/total duration are configurable with top-level `video`. Illustrated scenes adapt portrait/square/landscape layout; the art coordinate system remains 1080 × 1920. Legacy scenes retain their original layout.
- Supported SVG subset is path, ellipse, rect, line, text and groups/asset instances. Linear/radial gradients, paint color tracks, skew and compatible M/L/C/Q/Z morphing are supported. No arbitrary SVG/XML import, filters, IK, lip sync or character rig solver.
- One cubic Bézier per node, eased parameter motion; not arc-length constant-speed travel or arbitrary SVG path following.
- Palette validation checks token names, not perceptual contrast. Bounds/provenance are declared and validated structurally, not inferred from paths.
- Nested assets render, but layer overrides target the immediate asset's declared nodes, not a global dotted selector language for nested asset instances.
- Camera parallax is pan-relative. Nested depth contributions accumulate. No depth of field or 3D camera simulation.
- Fade is a short dip to the common paper background, not a temporal cross-dissolve. Timing follows compiled shot durations; the coffee benchmark remains 900 frames.
- Ordinary SVG paths are checked for presence; morph paths additionally require explicit matching command topology. Geometric correctness is not certified. Visual QA remains essential.
- Assets are generated by agent-authored vector code. No automatic prompt-to-SVG service or segmentation of flattened images is claimed.
- Narration is script metadata. The benchmark is silent; audio timing remains future work.

See [engine workflow](engine-workflow.md) for cue dependency authoring, asset inspectors, format settings and review reports.

## Validation

`npm run typecheck`, `npm run test:engine`, and `npm run preview:coffee` (PNG-only production bundle and Chrome renders). `python3 scripts/coffee-contact-sheet.py` uses Pillow to make the review sheet. Write per-run QA evidence and limitations under the generated preview run directory. No MP4 is required by these checks.

## Source entry points

- `src/index.ts` registers `Root`; `src/root.tsx` declares film, shot and asset preview compositions.
- `src/storyboard/example.ts` selects the default film from `src/examples/coffee/storyboard.ts`.
- `src/spec.ts` compiles the selected storyboard into `board`, `scenes` and `video`.
- `src/Video.tsx` sequences compiled scenes; `src/scenes/SceneView.tsx` shares shot behavior with standalone previews.
- `src/examples/coffee/cues.ts`, `shared.ts` and `shots/` contain story-specific timing and drawing composition.
- `src/storyboard/timeline.ts` exposes cue APIs implemented under `timing/`.
- `scripts/preview-report.mjs` orchestrates options → frame planning → PNG rendering → report; implementations are in `scripts/preview/`.

The old coffee-benchmark and storyboard/example modules retain compatibility exports. Prefer editing the owning implementation rather than growing these entry points.
